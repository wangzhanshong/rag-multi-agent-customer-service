# RAG 多智能体笔记本客服系统 —— 系统架构文档

## 1. 项目概述

本项目是一个基于 **RAG（检索增强生成）+ 多智能体（Multi-Agent）** 架构的笔记本电脑智能客服系统。系统采用 **调度-专家模式（Dispatcher-Specialist Pattern）**，由前端 Vue3 SPA、后端 FastAPI、向量数据库 Milvus、关系型数据库 MySQL 以及多个外部 API 服务协同工作，实现对笔记本售后问题的智能问答和服务网点导航。

## 4. 多智能体架构（核心）

### 4.1 架构模式：Dispatcher-Specialist（调度-专家模式）

```
                          ┌──────────────┐
                          │ Triage Agent │  ← 调度器：仅做意图分类
                          │   (调度智能体) │     无业务工具，不生成最终回复
                          └──┬───┬───┬──┘
                             │   │   │
                    handoff  │   │   │  handoff
              ┌──────────────┘   │   └──────────────┐
              ▼                  ▼                  ▼
      ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
      │ Tech Expert  │  │  Nav Expert  │  │General Agent │
      │  (技术专家)    │  │  (导航专家)   │  │  (通用闲聊)   │
      │              │  │              │  │              │
      │ Tool:        │  │ Tool:        │  │ Tool: 无     │
      │ rag_search   │  │ map_locate   │  │              │
      │              │  │ map_search   │  │              │
      │              │  │ map_distance │  │              │
      └──────────────┘  └──────────────┘  └──────────────┘
```

### 4.2 各 Agent 职责

| Agent | 名称 | 工具数 | Handoff | 职责 |
|-------|------|--------|---------|------|
| **Triage** | Triage Agent | 0 | → Tech, Nav, General | 意图分类，将用户问题路由到合适的专家 |
| **Tech Expert** | Tech Expert | 1 (`rag_search`) | 无 | RAG 检索技术知识库，回答笔记本售后技术问题 |
| **Nav Expert** | Nav Expert | 3 (地图相关) | 无 | 用户定位、搜索附近服务网点、计算距离路线 |
| **General** | General Agent | 0 | 无 | 处理闲聊和超出范围的问题，礼貌引导回笔记本售后话题 |

### 4.3 意图分类逻辑（Triage Agent System Prompt 核心规则）

```
用户意图判断逻辑:
├── 技术问题 (→ Tech Expert)
│   ├── 笔记本硬件故障 (蓝屏、无法开机、电池、散热、屏幕...)
│   ├── 笔记本使用问题 (系统安装、驱动、软件配置...)
│   └── 笔记本购买咨询、保修政策
│
├── 导航问题 (→ Nav Expert)
│   ├── 查找售后网点、维修点
│   ├── 查找品牌专卖店、体验店
│   └── 导航到某地点、计算距离
│
└── 其他问题 (→ General Agent)
    ├── 闲聊 (天气、笑话...)
    └── 超出范围的问题 (手机、家电...)
```

### 4.4 Handoff 机制

使用 OpenAI Agents SDK 原生的 `handoffs=[...]` 参数：

- SDK 自动为 Triage Agent 创建 transfer 工具函数 (`transfer_to_tech_expert`, `transfer_to_nav_expert`, `transfer_to_general`)
- Triage Agent 通过 LLM 推理，根据 System Prompt 中的规则选择目标 Agent
- 切换时自动传递对话历史，目标 Agent 可以获取完整的上下文

### 4.5 工具定义（Function Tools）

```
Tech Expert 工具:
└── rag_search(query: str) → str
    └── 调用 retrieval.py::retrieve()
        ├── 向量召回 (Milvus ANN) → Top-20
        ├── 关键词召回 (BM25) → Top-10
        ├── 合并去重 → Cross-Encoder 重排序 → Top-5
        └── 无结果时: jieba 关键词提取 → 多词单独搜 BM25

Nav Expert 工具:
├── map_locate_user(query: str="") → str
│   └── Baidu Maps IP 定位 API → 城市 + 经纬度
├── map_search_stations(keyword: str) → str
│   └── Baidu Maps POI 搜索 + 多品牌关键词过滤
│       关键词: 笔记本|电脑|维修|售后|服务中心|Lenovo|联想|ASUS|华硕|Dell|戴尔|HP|惠普
└── map_calculate_distance(origin, destination) → str
    └── Baidu Maps 驾车路线 API → 距离 + 预计耗时
```

## 5. RAG 检索管线架构

### 5.1 双路召回 + 重排序策略

```
用户提问
    │
    ▼
┌─────────────────────────────────────────────────────┐
│                   embed_query()                      │
│            DashScope Qwen3-Embedding                 │
│              1024维向量 + LRU缓存                     │
└──────────────────┬──────────────────────────────────┘
                   │
    ┌──────────────┴──────────────┐
    │                             │
    ▼                             ▼
┌───────────────┐          ┌───────────────┐
│  向量召回       │          │  关键词召回     │
│  (Milvus ANN)  │          │  (BM25)       │
│               │          │               │
│  索引: IVF_FLAT│          │  jieba 分词    │
│  度量: IP (内积)│          │  BM25 算法     │
│  nprobe: 16    │          │  k1=1.5       │
│  Top-K: 20     │          │  b=0.75       │
│               │          │  Top-K: 10     │
└───────┬───────┘          └───────┬───────┘
        │                          │
        │     ┌────────────────────┘
        │     │
        ▼     ▼
┌─────────────────────────────────────────────────────┐
│              合并 & 去重 (按 doc_id + chunk_text)     │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│         Cross-Encoder 重排序                          │
│         BAAI/bge-reranker-v2-m3                      │
│         对每个 (query, chunk) 对打分                  │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
              ┌────────────────┐
              │  返回 Top-5     │
              │  (含标题+正文+分数)│
              └────────────────┘
```

### 5.2 降级策略

| 故障组件 | 降级方案 |
|---------|---------|
| Milvus 不可用 | 跳过向量召回，仅使用 BM25 |
| Embedding API 失败 | 跳过向量化存储，仅 BM25 |
| Cross-Encoder 不可用 | 跳过多重重排序，按原始分数排序 |
| BM25 无结果 | jieba 提取关键词，逐词单独搜 BM25 |
| 全部无结果 | 返回空，Agent 诚实告知无法回答 |

### 5.3 文档处理管线

```
文件上传 (.txt / .md / .pdf)
    │
    ▼
┌──────────────────────────────────────────────┐
│  文本提取                                       │
│  .txt/.md → 直接读取                           │
│  .pdf → PyPDF2 提取                            │
└──────────────────┬───────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────────┐
│  文本切分 (LangChain RecursiveCharacterTextSplitter) │
│  chunk_size=500, overlap=50                   │
│  分隔符: \n\n → \n → 。→ ！→ ？→ ；→ . → ! → ? → ; → 空格 │
└──────────────────┬───────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────────┐
│  向量化 (DashScope Qwen3-Embedding)           │
│  批量处理, 每批 25 条                          │
│  失败 → 静默降级, 继续处理                      │
└──────────────────┬───────────────────────────┘
                   │
      ┌────────────┴────────────┐
      │                         │
      ▼                         ▼
┌──────────────┐        ┌──────────────┐
│  存入 Milvus  │        │  存入 MySQL   │
│  向量 + 元数据 │        │  文档元数据    │
│  (可选, 可降级)│        │  + 分块文本   │
└──────────────┘        └──────┬───────┘
                               │
                               ▼
                      ┌──────────────┐
                      │  更新 BM25   │
                      │  内存索引     │
                      └──────────────┘
```

### 5.4 BM25 索引实现

```python
class BM25Index:
    """
    纯 Python 实现的 BM25 关键词索引
    - 使用 jieba 进行中文分词
    - BM25 公式: score(D,Q) = Σ IDF(qi) × (f(qi,D) × (k1+1)) / (f(qi,D) + k1 × (1-b + b×|D|/avgdl))
    - 参数: k1=1.5 (词频饱和度), b=0.75 (长度归一化)
    - 启动时从 MySQL/Milvus 重建，无磁盘持久化
    """
```

```

    │
    ▼

    │
    ▼

    │

│  │ created_at  │              │ 创建时间                   │ │

│  conversations (对话会话)                                   │
│  ┌─────────────┬──────────────┬────────────────────────┐ │
│  │ id (PK)     │ session_id   │ 会话唯一标识 (UUID)       │ │
│  │ title       │ created_at   │ 会话标题 / 创建时间        │ │
│  │ updated_at  │ messages[]   │ 更新时间 / 关联消息        │ │

├──────────────────────────────────────────────────────────┤
│  messages (对话消息)                                        │
│  ┌─────────────┬──────────────┬────────────────────────┐ │

### 7.3 数据流向图

```
文档上传
    │
    ├──→ 文本 & 元数据 → MySQL (documents + doc_chunks)
    ├──→ 向量 → Milvus (laptop_knowledge)
    └──→ 关键词 → BM25Index (内存)

对话
    │
    └──→ 会话 & 消息 → MySQL (conversations + messages)
         (含 intent 分类 + sources JSON)

## 11. 关键设计模式与决策

### 11.1 优雅降级 (Graceful Degradation)

系统在所有外部依赖处都实现了 try/except 降级：

- Milvus 不可用 → 自动回退到纯 BM25 检索
- Embedding API 失败 → 文档仍然存储到 MySQL + BM25
- Cross-Encoder 不可用 → 按原始分数排序返回
- 所有降级均为静默处理，不影响用户正常使用

### 11.2 Agent 模型共享

所有 Agent 共享同一个 `OpenAIChatCompletionsModel` 实例，该实例包装了共享的 `AsyncOpenAI` HTTP 客户端。这复用了 HTTP 连接池，避免了不必要的资源消耗。

### 11.3 MCP 双重模式

Baidu Maps 功能以两种模式暴露：
- **内部工具模式** (`@function_tool`): 供 Nav Expert Agent 直接调用
- **MCP Server 模式**: 标准化外部集成接口，通过 `mcp` SDK 以 stdio 协议暴露

### 11.4 来源追踪

RAG 检索的来源文档在两层进行提取：
1. 从 Agent 运行历史中的 `function_call_output` 获取结构化数据
2. 从回复文本中通过正则 `【来源: xxx】` 匹配标注引用

来源信息随消息一同持久化到 MySQL 的 `messages.sources` 字段 (JSON 格式)。

### 11.5 启动时资源重建

BM25 内存索引在每次服务启动时从 MySQL 和 Milvus 重建，确保重启后数据完整。无需额外的磁盘持久化机制。
